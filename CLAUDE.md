# dwg2geo-r

R wrapper (extendr) over the pure-Rust `dwg2geo` conversion core: DWG → GeoJSON
in-process, no CAD/GDAL. On CRAN as `dwg2geo`.

## Architecture

- `src/rust/` — wrapper crate `dwg2geo-r` (staticlib, extendr-api). The
  conversion core is the `dwg2geo` crate from crates.io, pinned by
  `src/rust/Cargo.lock`. The wrapper crate's own `version` in Cargo.toml does
  NOT track the R package version and doesn't matter.
- `dwg_core_version()` reports the embedded **core** version (from Cargo.lock),
  not the wrapper crate.
- `src/rust/vendor.tar.xz` — all crate deps vendored for CRAN's offline
  builds. Gitignored; regenerated by `tools/vendor.sh`.

## Build (src/Makevars / Makevars.win) — hard-won CRAN constraints

Do not "simplify" these away; each one fixed a real CRAN rejection:

1. **`PATH` must include `$(HOME)/.cargo/bin`** around every cargo/rustc
   invocation. CRAN's macOS builders install Rust via rustup there and it is
   not on the default PATH — 0.2.3 ERRORed on all four macOS flavors with
   `cargo: command not found`.
2. **`rust_clean: $(SHLIB)` deletes `rust/target` and `rust/vendor` right
   after linking.** R (>= 4.5) scans leftover objects under `src/` for entry
   points like `abort()`; the Rust panic runtime in the intermediate staticlib
   triggered a "Found 'abort'" WARNING on 0.2.2. Side effect: every install is
   a full cargo rebuild (no incremental cache).
3. Offline vendored build when `vendor.tar.xz` exists (CRAN), online build
   otherwise (development). Max 2 jobs; cargo/rustc versions reported (CRAN
   policy).

## Vendoring

`./tools/vendor.sh` — must run with **cargo-vendor-filterer** installed. The
plain `cargo vendor` fallback vendors `r-efi` with GNU-extension Makefiles,
which triggers an R CMD check WARNING ("GNU extensions in Makefiles").

When bumping the embedded core: update `Cargo.lock`, then **regenerate
`vendor.tar.xz`** — the archive, not the lockfile, is what CRAN builds.

## Release checklist

1. Bump `Version:` in DESCRIPTION; update NEWS.md and cran-comments.md.
2. If the core changed: `./tools/vendor.sh`.
3. `R CMD build` the package, then `R CMD check --as-cran` on the tarball
   (not the source dir). Expect 0 errors / 0 warnings; local-only NOTE about
   HTML Tidy is the machine, not the package.
4. Submit with `devtools::submit_cran()` (interactive; confirm the email CRAN
   sends to the maintainer address). Commit the updated `CRAN-SUBMISSION`
   ("Record the pending CRAN submission (X.Y.Z, SHA ...)").
5. After acceptance: `git push`, annotated tag `vX.Y.Z` at the submitted SHA,
   GitHub release with the NEWS entry.

## Known check-result false positives

- "Possibly misspelled: Auditable" — real English word, kept in Title,
  explained in cran-comments.md.
- Tarball ~10 MB — vendored crates (mostly windows-sys/linux-raw-sys/libc);
  explained in cran-comments.md.
- crates.io links 404 for non-browser clients — link docs.rs in README instead.
